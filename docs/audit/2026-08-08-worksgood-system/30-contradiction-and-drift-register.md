## 1. Executive abstract

**`[FACT]`** The 14 upstream audits contain many repeated IDs for the same underlying conflict. This register deduplicates those records into 49 stable `WGDR-*` items while preserving source-ID crosswalks. The largest clusters are not isolated copy errors. They are incomplete authority migrations:

1. publication-derived completion replaced direct `Done`, but help, manuals, smoke policy, and tests still encode older generations;
2. Pi-first onboarding and handler-first routing advanced while setup, doctor, profiles, and service prose retained different product scopes;
3. review/evaluation moved from graph satellites to compact manifest-bound receipts, preserving completion safety while losing attempt visibility, cost attribution, and the agency-learning join;
4. federation/review/exec/Pilot prose often describes ratified or complete enforcement while implementation provides a narrower spark, CLI protocol, or same-user boundary;
5. point-in-time reports and designs are preserved correctly but lack status, applicability, and supersession edges.

**`[VERIFIED BEHAVIOR]`** Current `wg done --help` still advertises five legacy flags, while `src/main.rs` rejects any of them and routes bare completion through `completion_done::run`. Current completion therefore remains publication-derived; stale surfaces must not be treated as an alternate authority (`src/cli.rs:528-554`; `src/main.rs:1261-1274`; command `cargo run --quiet --bin wg -- done --help`).

**`[FACT]`** The most important architecture decision from `23-evaluation-evolvability-cutover.md` is adopted without smoothing over its policy questions: **keep the v3 manifest-bound completion valve as the only source-lifecycle authority; add a first-class append-only review-attempt/event ledger plus non-authoritative virtual projections; add a separate exactly-once learning projector that cannot complete, retry, reopen, publish, or fail source work.** Restoring `.assign-*`, `.flip-*`, or `.evaluate-*` as ordinary schedulable tasks would recover visibility by reintroducing the lifecycle coupling the cutover removed (`23-evaluation-evolvability-cutover.md:13-25,224-270`).

**`[INFERENCE]`** The priority is not “make all prose match the newest wording.” It is to elect typed authorities by question, encode source/derivative relationships, and either implement or explicitly narrow claims. Historical evidence should remain immutable and gain applicability metadata rather than be silently rewritten.

## 2. Method, labels, and authority rules

### 2.1 Completeness and deduplication

All 15 bundle artifacts were read, including their maps, findings, contradiction sections, recommendations, limitations, and evidence appendices—not only dependency summaries. Repeated IDs were merged only when they had the same conflicting claims and resolution. A merged row retains all material upstream IDs in **Crosswalk**. Closely related items remain separate where owners or adjudications differ (for example completion help versus smoke-gate authority).

### 2.2 Statement and evidence labels

- **`[OBSERVED FACT]`**: directly present in repository bytes or structured graph data.
- **`[VERIFIED BEHAVIOR]`**: an executed command/test in an upstream audit or this register observed it.
- **`[DOC-CLAIM]`**: normative or descriptive prose, not itself runtime proof.
- **`[INFERENCE]`**: reasoned consequence; falsifier or boundary is stated where material.
- **`[RECOMMENDATION]`**: proposed resolution, never disguised as current behavior.
- **Kind:** `fact` means two checkable authorities disagree; `ambiguity` means scope/desired policy is not elected; `suspected drift` means evidence suggests divergence but the final comparison is incomplete.

Evidence classes follow the charter: current source and candidate-built behavior control current implementation; current tests prove only the selected path; ADR/design prose controls intent only when its status/applicability says so; AGENTS/CLAUDE alone never establishes product behavior.

### 2.3 Severity and state

`S1` high, `S2` medium, `S3` low, `S4` informational. States are **open**, **resolved**, **apparent/non-issue**, **superseded**, or **accepted debt**. Confidence is high/medium/low and applies to the recorded contradiction, not automatically to impact likelihood.

## 7. Cross-cutting adjudication program

### 7.1 Immediate factual synchronization

1. **`[RECOMMENDATION]` P0:** publish generated authority matrices for completion, lifecycle, model surfaces, ingest seams, and evaluation planes. Each row must name command, default, bypass, durable evidence, lifecycle authority, learning effect, and active test.
2. **`[RECOMMENDATION]` P0:** remove or implement unreachable Done flags; classify every completion smoke/test as current, compatibility, historical-retired, or red-first.
3. **`[RECOMMENDATION]` P0:** align bare launcher, Pi-only setup, profile selection, and route-aware doctor as separate journeys.
4. **`[RECOMMENDATION]` P0:** narrow absolute federation/review/Pilot claims immediately where the enforcement prerequisite is absent (custody process isolation, signed audit chain, remote coordinator, real-host check, credential wiring).
5. **`[RECOMMENDATION]` P1:** give every design/ADR/report bundle `status`, `observed_revision`, `applies_to`, and `superseded_by`; do not rewrite historical findings into present tense.

### 7.2 Architecture decisions rather than prose edits

1. **Evaluation cutover:** retain v3 completion valve as sole source-lifecycle consumer. Canonical new representation is append-only review event/attempt ledger; virtual projections are read-only/non-schedulable. Exactly-once learning is a separate projector with no lifecycle/publication capability (`EVC-REC-001..006`).
2. **Completion compatibility:** isolate v2/legacy writers and encode their reachability; no new path may mutate status outside lifecycle/v3 authority.
3. **Remote execution:** either build a coordinator-owned offer→claim→grant→renew→run→accept/finalize state machine or reject remote placement as explicitly manual.
4. **Federation custody/recovery:** same-user API minimization is not hostile-worker isolation. Production security claims require a separate authenticated signer and transition-bound recovery.
5. **Documentation:** choose a declared source graph. Generated derivatives must be checked; curated indexes must not claim estate completeness.
